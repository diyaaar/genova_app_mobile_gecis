beta journey against the declared compatible backend. Not a synthetic preview or

## Ordered work

1. Reconcile exposed routes: native Auth/choir/repertoire/chat where included and
   permanent WebViews. Every exposed action must work against deployed dependencies;

   silently removing them from scope. Confirm beta group and destination before sending.
2. Produce the reproducible signed candidate using approved credentials/build path;
   verify no test-only guards/secrets, exact source/config/lockfiles/build ID. Install
   through the approved destination and run the matrix below with agent automation.
3. Fix actual beta blockers in bounded briefs, rerun affected integration, record
   crash/feedback and recovery route, then hand accepted beta evidence to P6.

## Beta acceptance matrix

| Journey | Positive and negative acceptance |
|---|---|
| Invite/login | Valid invitation/account; invalid/revoked invite and wrong account refused without new membership; preserve 010's unrun historical rows until truly exercised |
| Choir selection | Zero/one/multiple memberships; server-confirmed current choir; A-only user cannot reach B, dual member switches safely |
| Repertoire/PDF | Actual private file and current annotations visible; page navigation/nonblank content; expired/refused/error states; no Drive account dependency |
| Audio | Actual protected audio, foreground seek/navigation continuity; invalid format/error/refusal visible; no claim for unshipped background support |
| Permanent WebViews | Profile/other exposed routes, file consent/return/back, native-owned session and safe lease; expired session and account actions |
| Relaunch/network | Cold reopen with secure session, cancellation and network interruption/retry; missing offline features stated, no offline-library claim from cache |
| Exit/isolation | Logout, choir/role/member changes, queues/cache/temp cleanup; next online request denied after revocation; previous choir content cannot persist visibly |
| Installation/update | Exact signed build installed; launch/update/reopen verified; no debug/guarded build promoted as beta |

Test chef/section leader/chorist as applicable, and two synthetic independent choirs
even if the real first cohort is only one choir. Synthetic tenant tests do not prove
second-customer onboarding; that remains P6. Define the actual role/device/network
matrix in the brief. No actual invitation/email/account mutation without matching scope.

## Device and authority boundary

The agent performs Android/iOS tests. If a physical device is required but unavailable,
record the exact missing access and complete eligible emulator checks; **installed
physical-beta acceptance stays NOT RUN**. Do not ask the owner to tap, scroll or
manually verify. Necessary credential/device access is not manual QA and may require
the owner's involvement. No indefinite retries or automatic distribution to contacts.

Android-first beta does not require pretending iOS physical acceptance is complete;
retain A5/004's remaining two-platform rows for P7, without deleting them. Current
platform-sensitive iOS source checks already belong to P2 and later affected changes.

## Acceptance and handoff

Every included feature, actual target, signed build and required beta scenario has
dated evidence; unresolved security/data-loss/core-flow failures block beta. Record
what the beta deliberately does not yet ship, with P6/P7 ownership. Signed artifact
identity, reproducible build and recovery are retained; disposable build copies cleaned.

Output: accepted installed-beta record + prioritized actual blockers/feedback + full
scope remainder. User announcement/upload/public release are separate operations.
Advance to P6 only after required P5 rows pass; prepare independent decisions if blocked.
