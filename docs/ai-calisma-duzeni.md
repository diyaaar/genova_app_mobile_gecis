# AI working approach

Updated 13 October 2026. [AGENTS.md](../AGENTS.md) owns current agent guidance.
This page offers a lightweight working pattern, not an additional rule system.

Understand the requested outcome, inspect relevant sources, make the necessary
changes, verify the affected behavior and report the result. Adapt task size,
research, refactoring and test strategy to the work. Continue useful authorized
work when an independent part is blocked. Ask only for a genuinely missing decision.

Use [briefs](briefs/_TEMPLATE.md), [handoffs](templates/ajan-devir.md) and checkpoints
when they make the work easier to resume or review. No mandatory startup checklist,
fixed attempt count, model-tier assignment, agent hierarchy or commit format applies.
Coordinate concurrent contributors by ownership and integration needs; select an
isolated worktree or sequential work when actual conflicts require it.

Keep evidence proportional and honest: what changed, what was tested, environment,
result and remaining uncertainty. Product safety, tenant isolation and real acceptance
criteria continue to matter. Historical test results are not fresh production proof.

Resource use follows measured capacity and the task, rather than an inherited numeric
quota. Reuse expensive setup where useful and clean owned disposable outputs without
removing unrelated data. Historical limits are not current operational instructions.

Update the relevant project status when it changes; avoid duplicating the same history
across indexes. This does not authorize changes to personal/global agent memory.

The earlier method and its rationale remain in Git history and the dated
[source analysis](ai-calisma-yontemi-kaynak-analizi.md) and
[repository analysis](ai-calisma-yontemi-repo-incelemesi.md).
